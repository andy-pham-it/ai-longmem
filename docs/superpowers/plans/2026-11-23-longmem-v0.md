# longmem v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a free-tier Supabase-backed store of experiential memory (mistakes, misunderstandings, lessons) whose catalogue is injected into every OpenCode session, and a CLI for writing, searching, reinforcing and superseding entries.

**Architecture:** One Postgres table plus five SQL functions do the ranking, dedupe and supersede atomically; a single Supabase Edge Function (Deno) is the only HTTP API; a self-contained OpenCode plugin fetches `/index` once per session and appends it to the system prompt via `experimental.chat.system.transform`; a Node/TypeScript CLI covers everything a hook cannot do. No embeddings, no local database.

**Tech Stack:** Postgres 15 (Supabase free tier) with `pg_trgm`, `unaccent`, `vector`; Supabase Edge Functions (Deno) with `npm:@supabase/supabase-js@2`; Node 22 + TypeScript (ESM) + `tsx`; vitest for pure-function tests; `@opencode-ai/plugin` 1.15.6 for the hook.

**Spec:** `docs/superpowers/specs/2026-11-23-longmem-design.md`

## Global Constraints

- Free tier only: one Supabase project, no paid add-ons, no local Postgres.
- `trigger` is required and must name a recognisable situation. Reject platitudes ("be careful", "verify before claiming", "communicate clearly").
- Default `scope` is `global`. `project` only with an explicit `--project`.
- The invariant is **bytes, not rows**: `GET /index` defaults to 8192 rendered bytes, configurable.
- Session-start hook must never block a session: 1500 ms timeout, failure is silent, the existing agent-memory blocks remain the offline floor.
- Nothing leaves Supabase: no embeddings, no LLM call from server or CLI in v0.
- Supersede, never delete.
- No auto-insert: `/write` never runs from a plugin; candidates are proposed and confirmed.
- English for code, identifiers, comments, docs, commit messages.
- Node ≥ 22, TypeScript `strict`, ESM (`"type": "module"`).
- New dependencies limited to: `tsx`, `vitest`, `@opencode-ai/plugin` (types), and `npm:@supabase/supabase-js@2` inside the Edge Function only.
- `project_key` = normalised git origin `host/owner/repo`, fallback `path:<absolute-directory>`.

## Review Focus

1. **Network down or slow at session start.** The session must start normally, with no visible error. Test in Task 10: config renamed away → OpenCode still opens a session.
2. **Corpus larger than the byte budget.** `/index` must cut at a line boundary, never mid-line, and report `truncated: true` plus `total`. Test in Task 4.
3. **A platitude slipping into the store.** `POST /write` must return 400 naming the offending rule. Test in Task 5.
4. **Vietnamese without tone marks.** `recall "kiem tra"` must find "kiểm tra". Test in Task 6.
5. **Dedupe false positive.** A genuinely new lesson that shares words with an existing title must not be silently dropped: 409 with `reinforce` / `supersede` / `force` choices. Test in Task 5.

## Decisions this plan settles (spec §16)

- **Test strategy:** pure functions (`render`, `validate`, `projectKey`, `router`) are unit-tested with vitest. SQL functions and HTTP handlers are verified by `curl` against the deployed project with printed expected output — no local Postgres.
- **`render-block`** is a CLI command (needs the same rendering code as `/index`, and hooks cannot be trusted to write files).
- **`related`** returns active rows only, plus the one-hop `replaces` object when the row superseded something. No chain walking.
- **`candidates`** is offline in v0: it prints the write checklist and the 10 newest active `title — trigger` lines so the agent can avoid duplicates. It reads no transcript.
- **Edge Function layout:** `index.ts` (router + handlers), `_shared/*.ts` (pure, Deno-safe, also imported by CLI and vitest).
- **CLI:** `tsx src/cli.ts`, exposed as `npm run longmem -- <cmd>`; no build step.
- **Plugin install:** copy `plugin/longmem.ts` into `~/.config/opencode/plugins/` (that directory is auto-scanned; no `opencode.json` change).
- **Hook trigger:** the plugin registers `experimental.chat.system.transform` with a per-session cache, rather than subscribing to `session.created`. The spec's outcome is unchanged (the block is in the system prompt on the first request of every session, without the agent asking), and it removes an event subscription, an ordering dependency between two hooks, and a second code path. The cache makes it one HTTP call per session, not one per model turn.

### Task 2: Schema, touch trigger, SQL functions

**Files:**
- Create: `supabase/migrations/0001_init.sql`, `supabase/verify/0001_verify.sql`

**Interfaces:**
- Produces (all `security definer`, `stable` unless noted, called via `supabase.rpc`):
  - `longmem_index_rows(p_project_key text) returns setof memories` — active rows where `scope='global' or project_key=p_project_key`, ordered `pinned desc, reinforced_count desc, kind_rank, updated_at desc` (`kind_rank` = preference 0, lesson 1, mistake 2, misunderstanding 3, fact 4).
  - `longmem_search(p_query text, p_project_key text, p_k int, p_kinds text[], p_tags text[], p_by text) returns table (…memories columns…, score real, replaces_id uuid, replaces_title text, replaces_created_at timestamptz)` — `p_by='recall'` ranks by `similarity(search_text, q)`, `p_by='related'` by `similarity(lower(unaccent(trigger)), q)`; hard filter `status='active'` and scope; `q := lower(unaccent(p_query))`.
  - `longmem_dedupe(p_title text, p_scope text, p_project_key text) returns table (id uuid, title text, similarity real)` — best active match in the same scope, `limit 1`.
  - `longmem_cross_project_similar(p_title text, p_project_key text) returns table (id uuid, title text, project_key text, similarity real)` — best match in a *different* project.
  - `longmem_supersede(p_old uuid, p_new jsonb) returns uuid` — inserts the new row, sets old `status='superseded', superseded_by=new.id` in one function (atomic), returns the new id.
  - `longmem_counts() returns jsonb` — counts by scope, kind, status and `pinned`.

- [ ] **Step 1: Write the migration (table + trigger + indexes)**

Table DDL is spec §7 with one correction: `search_text text not null default ''` (plain column) because `unaccent` is not immutable and the spec's `generated always as` would be rejected. Add `create extension if not exists vector;` because `embedding vector(768)` is declared now on purpose (spec §13). The check constraint `scope_project_key` stays exactly as spec.

```sql
create or replace function public.memories_touch() returns trigger
language plpgsql as $$
begin
  new.search_text := lower(public.unaccent(
    coalesce(new.title,'') || ' ' || coalesce(new.trigger,'') || ' ' || coalesce(new.body,'')));
  new.updated_at := now();
  return new;
end $$;
create trigger memories_touch_trg before insert or update on public.memories
  for each row execute function public.memories_touch();

alter table public.memories enable row level security;
-- no policy for anon or authenticated, by design (spec §12)
revoke all on public.memories from anon, authenticated;
```

- [ ] **Step 2: Write the five functions**

Signatures as in **Produces**. `longmem_supersede` validates the jsonb payload with the same rules as the HTTP layer (`scope`/`project_key` consistency, `char_length` limits) and raises `check_violation` with a readable message otherwise.

### Task 7: `POST /reinforce`, `/update`, `/supersede`, `/promote`

**Files:** Modify `supabase/functions/longmem/index.ts`

**Interfaces:**
- `POST /reinforce {id}` → `200 {id, reinforced_count}`; increments and sets `last_reinforced_at`; `404` when the id is not active.
- `POST /update {id, title?, trigger?, body?, tags?}` → `200 {action:"updated", entry}`; only the given fields, `search_text` and `updated_at` follow from the trigger; never changes `scope`, `kind`, `status`, counters. `409 needs_decision` when the reworded title now trips dedupe against a *different* row.
- `POST /supersede {id, ...NewEntry}` → validates the new entry, then `longmem_supersede`, `201 {action:"superseded", entry}`; `409` when the old row is not `active`.
- `POST /promote {id}` → `200 {action:"promoted", entry}`; `global` scope and `project_key = null`; `409` when already global.

- [ ] **Step 1: Implement the four handlers**

All id-taking handlers first `select … where id=$1 for update` semantics via the RPC where needed; plain updates are fine for reinforce/update/promote.

- [ ] **Step 1: Implement the plugin, self-contained**

No imports beyond `node:fs`, `node:path`, `node:os`, `node:child_process`, and `import type { Plugin }` (type-only, erased at runtime). Behaviour:

```ts
const cache = new Map<string, string>();          // sessionID -> block
const inflight = new Map<string, Promise<string>>();

server = async ({ directory }) => ({
  "experimental.chat.system.transform": async (input, output) => {
    const key = input.sessionID ?? "default";
    let block = cache.get(key);
    if (block === undefined) {
      block = await (inflight.get(key) ?? startFetch(key, directory)).catch(() => "");
      cache.set(key, block); inflight.delete(key);
    }
    if (block) output.system.push(block);
  },
});
```

`startFetch` reads the config with `mode & 0o077` tolerated read-only (do **not** throw inside the hook), derives `project_key` with `execFileSync("git", ["remote","get-url","origin"], { cwd: directory, timeout: 400 })` wrapped in try/catch, calls `${endpoint}/index?project_key=…`, aborts at 1500 ms via `AbortSignal.timeout(1500)`, returns `json.block ?? ""`. Every throw is swallowed to `""`. Log one line with `client?.app?.log?.({ service: "longmem", level: "debug", message })` if available, else nothing.
